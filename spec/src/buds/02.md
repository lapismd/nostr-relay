## Lapis implementation

The relay exposes `PUT /upload` for authenticated users, computes a hash over the received bytes, verifies it against the optional `X-SHA-256` header and the signed token, stores bytes, and returns a descriptor.

| Source requirement | Lapis behavior | Classification | Reason and compatibility impact | Evidence/status |
| --- | --- | --- | --- | --- |
| Upload response | New blobs return `201`; an existing byte blob returns `200`. The declared and signed hash is checked against the request body. | Implemented | Duplicate status is determined before dispatch to the storage handler. | `internal/blossom/server.go`, `internal/blossom/upload.go` |
| Persistence ordering | The maintained upload handler verifies and bounds exact request bytes, then atomically replaces the blob file before recording ownership. Index failures propagate to the HTTP response. | Implemented | An index failure may leave an unreferenced file, but cannot expose an index entry pointing to missing bytes. | `internal/blossom/upload.go`, `zooid/blossom.go` |
| Empty body | Zero-byte blobs and their standard SHA-256 digest are accepted by direct upload and preflight. | Implemented | The maintained handler no longer inherits the generated handler's non-standard minimum size. | `TestMaintainedUploadAcceptsZeroByteBlob` |

Update this audit when the pinned definition or implementing relay/Community behavior changes.
