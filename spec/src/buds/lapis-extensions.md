# Lapis Blossom extensions

Lapis uses signed Nostr events and registry manifests as the authority for application use of blobs. A blob descriptor's MIME type and NIP-94 tags describe file bytes; they do not prove that an avatar or plugin release uses those bytes.

Signed upload authorization may declare `lapis-purpose`, `lapis-plugin`, and `lapis-slot` tags. Values are lowercase labels of at most 128 characters; the server stores them per uploader and hash. They are uploader claims, not proof that a profile or plugin release uses the blob.

An owner may add `tag.m`, `tag.x`, `tag.size`, `tag.purpose`, `tag.plugin`, or `tag.slot` query parameters to `GET /list/<pubkey>`. Different keys combine with AND; repeated values within one key combine with OR. `limit` defaults to 100 and is capped at 1,000. `cursor` is the last returned hash; responses retain the BUD-12 descriptor array and use newest-first ordering with hash ties. The optional `lapis` field contains the owner's declared values. Owner authorization is required. Listing now uses an indexed owner/hash projection, with a one-time migration of existing unsigned blob entries. Lifecycle-based filtering remains planned.

Admins and configured managers may read the persisted report queue at `GET /api/assets/reports` with a signed BUD-11 `list` token. Results are newest-first, bounded, and paged by report-event ID. An owner may read their append-only lifecycle at `GET /api/assets/history`; admins and configured managers may supply an `owner` pubkey. The endpoint requires a signed `list` token, caps `limit` at 500, and returns a stable `occurred_at:id` cursor. Upload, reference-add, reference-remove, blocked-delete, and delete actions remain after the current blob row is removed. These are Lapis extensions, not upstream BUD requirements.

An upload begins unreferenced. An accepted current kind `0` event establishes a retained `picture` or `banner` reference only when its author owns that local hash; linking another owner's blob cannot pin it. Replacement and removal update current references transactionally and append lifecycle records. Explicit deletion is checked before storage and blocked while that owner's retained reference requires the blob; the upstream index continues to keep shared bytes while another owner remains. Startup backfills recoverable current profiles, but profiles overwritten before this migration are not recoverable as historical references. Registry-manifest artwork projection remains pending; plugin artwork changes must create a new signed release under the existing registry review process.
